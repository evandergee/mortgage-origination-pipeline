# Mortgage loan-origination pipeline analytics (SQL Server + Power BI)

> Built by Evan Gilb, drawing on 15 years in mortgage lending, with Claude as an AI coding partner.

The **production side** of the mortgage business: applications moving through
underwriting to funding, modelled as an **event log** and analysed the way a
pipeline / production analyst would — funnel and pull-through, cycle time and
bottlenecks, SLA breaches, the rate-lock desk, loan-officer scorecards, and a
pull-through-weighted funding forecast. Plus a **Power BI semantic model** and a
4-page report build guide ([`powerbi/`](powerbi/)).

```powershell
.\run_analysis.ps1
```

Generate ~9,000 applications and ~89,000 events → derive the stage model → build
the analytics layer → validate → guided tour. Needs SQL Server (Express is fine)
with the Chinook database (the `orig` schema is created there) and `sqlcmd`.
~1–2 minutes, most of it generating data.

> Data is **synthetic** — generated by [`00_generate_pipeline.sql`](sql/00_generate_pipeline.sql).
> No real applicant data.

---

## The model — an event log

`orig.ApplicationEvent` is the source of truth: one row per thing that happened
to a loan (`Application`, `Processing`, `Appraisal Ordered/Received`,
`Underwriting Submitted`, `Conditional Approval`, `Clear to Close`, `Closing`,
`Funded`, `Delivered`, `Denied` / `Withdrawn` / `Cancelled`, `Rate Locked` /
`Extended` / `Expired`).

Everything else is derived from it:

| Object | What it is |
|---|---|
| `orig.vStageDurations` | one row per application per stage it occupied — entered / exited dates, **calendar days and business days** (via `orig.Calendar`), how the stage ended. `LEAD()` over the event log. |
| `orig.vApplicationCurrent` | one row per application — its current state, how long it has sat there, pipeline / funded / fallout flags. |

Business-day math uses `orig.Calendar` (weekday & not a US federal holiday) with a
running `BusinessDaySeq`, so days-between is two key lookups, not a range scan.

## The analytics layer

| View | Question it answers |
|---|---|
| `orig.vFunnel` | Of the apps taken in month X, what share reached each stage and funded? (raw and excluding still-in-pipeline) |
| `orig.vCycleTime` | Median and p90 days application → funded, by cohort (`PERCENTILE_CONT`) |
| `orig.vStageCycleTime` | Median / p90 **business days** spent in each stage — where the time goes |
| `orig.vSLABreaches` | Live loans sitting in a stage past its business-day SLA |
| `orig.vPipelineAging` | Live pipeline by stage × age bucket (fresh vs stale) |
| `orig.vLockExpirations` | Active rate locks by time to expiration (next 7 / 14 / 30 days) |
| `orig.vLoanOfficerScorecard` | Trailing-12-month production per LO — units, volume, pull-through, cycle time, purchase mix |
| `orig.vPullThroughForecast` | Expected $ to fund in the next 30 / 60 / 90 days = Σ (pipeline loan amount × historical funding rate for its stage), timed by the median days-to-fund from that stage |

## Power BI layer (`powerbi/`)

| File | |
|---|---|
| `01_semantic_views.sql` | `pbi` schema — a star (`DimDate` / `DimLoanOfficer` / `DimStage` / `FactApplication` / `FactStageDuration` / `FactForecast`) shaped for Import |
| `measures.dax` | ~30 measures — pull-through, funnel conversion, cycle time (median/p90), SLA breaches, lock desk, pull-through-weighted forecast, and daily time intelligence (YTD / YoY / rolling 3-month) |
| `model-guide.md` | connect, relationships (incl. the inactive funded-date role), mark-as-date-table, formatting |
| `report-guide.md` | 4 pages visual-by-visual with wireframes: Executive · Cycle Time & Bottlenecks · Live Pipeline & Forecast · Loan Officers |

## Skills demonstrated

- Event-sourced modelling — deriving stages, current state, and durations from an
  append-only event log (`LEAD`, `ROW_NUMBER`, gaps-and-islands)
- Business-day / SLA math against a holiday calendar
- Funnel / cohort / pull-through analysis
- `PERCENTILE_CONT` for median & p90 cycle times
- A pull-through-weighted pipeline forecast (historical rates joined back onto the live book)
- Set-based synthetic-data generation; indexing an events table for view performance
- Automated data-quality validation
- **Power BI** star-schema modelling, a DAX measure library, and time intelligence with an inactive date role
